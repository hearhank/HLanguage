# 07 · 与 Rust / Zig 功能对比

定位：H 以**数据生命周期为第一原则**，站在 Rust（所有权）与 Zig（显式与无隐藏控制流）的肩膀上，目标是"静态编译 + 脚本化 + 一切都是数据"。本模块把 H 的类型、内建能力与 Rust、Zig 逐项对照，既用于定位（H 是什么），也用于自查（H 的每一项设计是否落到了实处）。

三者的哲学一句话：

- **Rust**：编译器全知——借用检查、trait、宏在编译期把安全与抽象铸死，运行时零成本。
- **Zig**：运行时全显式——allocator、指针、error、`defer` 都在明面上，无隐藏控制流，编译期用 `comptime` 补抽象。
- **H**：生命周期可见但自动——单一所有权 + 显式 `move`，销毁安全交给**运行时双向引用通知**（内建但可见的成本），不做 Rust 式编译期借用检查（约束过强），不用 GC（隐藏控制流）。

## 总览

| 维度 | H | Rust | Zig |
|---|---|---|---|
| 内存形状 | 块（连续）/ 树（引用图），类型即形状 | 值（栈）/ 引用（堆）由使用方式决定 | 值（栈）/ 切片与指针，堆经 allocator |
| 所有权 | 单一所有权 + 显式 `move`，运行时通知 | 单一所有权 + 隐式移动 + 编译期借用检查 | 无所有权模型，手动管理 |
| 销毁 | 作用域退出自动销毁（树），指针被通知置空 | 作用域退出 `Drop`，借用关系编译期保证不悬垂 | `defer` 显式释放，悬垂靠自觉 |
| 错误 | `error T` union + 未处理即终止 | `Result<T, E>` + `?` | `error union` + `try` / `catch` |
| 并发 | 执行体统一（线程/协程）+ M:N + Channel | 线程 + async/await + mpsc | 线程 + 有限 async，Channel 自建 |
| 对象系统 | class 组合（import/hide/alias，无继承）+ 静态接口 | trait（动态分派或单态化） | struct 方法（无接口/无继承） |
| 序列化 | 内建 `to_bytes`/`from_bytes`（可逆自描述，全类型） | serde（库，需 derive） | std.json + 手动序列化 |
| 元编程 | 无宏（函数/组合承担抽象） | 宏（声明式 + 过程式） | `comptime`（编译期执行） |
| 工具链 | 双后端：解释器（脚本）+ C 原生编译 | rustc/cargo | zig build |
| 内存安全策略 | 运行时通知（防悬垂）+ 编译期读写分离 | 编译期借用检查 | 无内建保护，显式即安全 |
| 隐藏控制流 | 无（同 Zig 哲学） | 有（`?`、panic、async 隐式状态机） | 无 |

## 生命周期与内存对照

| 机制 | H | Rust | Zig |
|---|---|---|---|
| 所有权 | 单一所有权，`move` 显式转移 | 单一所有权，移动隐式（可显式 `move` 闭包捕获） | 无 |
| 借用 | `ref T`：写透别名，运行时双向引用通知 | `&T`/`&mut T`：编译期借用检查 | 裸指针，无检查 |
| 悬垂防护 | 树对象内嵌被引用链表，销毁时通知所有指针置空 | 借用检查器拒绝悬垂代码 | 无（靠 allocator 纪律 + 防御） |
| 销毁 | 作用域退出自动销毁（树），块零成本 | `Drop` trait | `defer` 显式 |
| 循环引用 | 已决策"先禁用"（实例级成环禁止） | `Rc<RefCell>` 可成环（泄漏） | 手动，成环即泄漏 |
| 分配器 | 显式 allocator（设计，动态块数据区经 allocator） | 全局分配器（默认隐藏） | **allocator 显式传参**（语言级） |
| 拷贝语义 | 块=memcpy，树=引用（不复制） | `Clone`/`Copy` trait 控制 | 赋值即拷贝（值），无自定义 |
| 不可变默认 | 是（`mut` 显式） | 是（`mut` 显式） | 是（`var` 显式） |

## 行为组织对照

| 机制 | H | Rust | Zig |
|---|---|---|---|
| 函数签名 | `x: T` / `ref T` / `move T`；返回 `move/ref/T` | 引用标注 `&`/`&mut`，移动隐式 | 指针显式 `*`，无所有权语义 |
| 组合（替代继承） | class `import` + `hide` + `alias`，方法表提升 | trait 默认方法 + 组合（struct 字段） | 无继承，组合即字段 |
| 接口 | 静态绑定（编译期单态化，无运行期接口值） | `trait`（静态或动态分派） | 无接口；用 `comptime` + 编译期约定 |
| 同名冲突 | 编译期强制处理（hide/alias，R11） | 方法重载受限，trait 冲突编译期报错 | 无方法集，无此问题 |
| 模式匹配 | `match` 穷尽（R10），无绑定/守卫 | `match` 富模式（绑定、守卫、嵌套） | `switch` 穷尽（有限模式） |
| 方法派发 | 静态派发 `Type_method(self,...)` | 静态（单态化）或 `dyn` 动态 | 静态（普通函数 + self 参数） |

## 设计借鉴与取舍

- **从 Rust 借鉴**：单一所有权、作用域销毁、局部类型推断、穷尽 match、不可变默认。
  - **差异**：移动**显式**（Rust 隐式）；不做编译期借用检查，改用**运行时双向引用通知**（防悬垂成本可见，换来约束松、学习曲线平）。
- **从 Zig 借鉴**：error union 形态、无隐藏控制流、显式 allocator、指针显式标注、`comptime` 思想（H 用编译期方法表/类型注册表替代）。
  - **差异**：Zig 无所有权（H 补上）；Zig 无对象组织（H 补上 class 组合 + 接口）。
- **H 独有**：两种内存形状（块/树）是类型系统根基；字节化全类型内建（含树压平/恢复）；双后端（脚本与编译同一份代码）；执行体统一 + 引用不跨执行体；类型即访问模式。

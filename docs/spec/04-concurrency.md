# 04 · 并发

## 执行体（线程/协程统一）

- 执行体 = **数据 + 处理逻辑** 的统一组合（语言层面不区分线程/协程）。
- 是程序作用域树的一个分支，有自己的作用域结构。
- **调度：M:N**——语言级协作式执行体，映射到多个系统线程。
- 退出时，其拥有的数据自动销毁（若有所有权）。

## 协作式调度（已交付，`src/evaluator.js`）

- 执行体 = JS 生成器（独立调用栈）；调度器 = 就绪队列 + 等待唤醒（单线程事件循环——M:N 的 M=1 形态，结构上是正确的协程模型，可映射 worker_threads）。
- `spawn fn()`：创建执行体入队，不立即执行；`yield`：让出调度权；主执行体结束后调度器跑完队列。
- `Channel(n)`：容量缓冲 + 等待者队列——`send` 满挂起、`recv` 空挂起，空位/数据就绪唤醒。
- 跨执行体数据：Channel 传深拷贝（树跨执行体边界近似 move；ref 参数在 spawn 场景退化为值绑定——符合"引用不跨执行体"）。
- 示例：`examples/concurrency.h`（生产者/消费者经典交替）。

## M:N 并行（已交付，`h run --threads N`）

- 主线程协调器（`src/parallel.js`）：Channel 注册表路由（单点串行 = 无竞争）+ 输出聚合 + spawn 轮询分派；worker 线程（`src/worker_host.js`）：执行体宿主（各自协作式队列）。
- 跨线程数据 = postMessage 结构化克隆（深拷贝）——兑现"引用不跨执行体"；global channel 以主线程分配的 id 同步到 worker。
- 执行体 runtime 错误跨线程回传报告。
- **确定性取舍**：多线程模式 print 输出顺序不保证（与单线程模式可能不同）——M:N 的性能收益换输出顺序；单线程模式（默认）完全确定。
- 原型级简化：`SharedRead`/`Exclusive` 保持语义标记（单点路由已无竞争）。

## 跨执行体规则

- **引用（指针）不跨执行体**。跨执行体传递数据只有两条路：
  1. **move**——所有权转移（专属数据，无需访问模式；单一所有权保证无竞争）；
  2. **模式化共享数据**——声明了访问模式的数据（含全局）。
- 这使双向引用通知永远在单一执行体内（无跨线程同步，成本确定）。

## 访问模式（类型即模式）

- 跨执行体**共享的数据必须声明访问模式**；全局默认共享，必须声明。
- 模式是**类型的一部分**，用内建包装类型表达；编译器按类型分派实现：

| 模式 | 包装类型 | 实现 |
|---|---|---|
| 单写单读 | `Channel<T>` | 无锁通道（SPSC） |
| 单写多读 | `SharedRead<T>` | 读写锁 / 共享不可变 + 版本 |
| 多写单读 | （内建） | 专属实现 |
| 多写多读 | `Exclusive<T>` | 互斥 / 原子 / 事务 |

- 模式适用于单个数据与集合数据（数组等）。
- 内建而非库：实现需要编译器/运行时的底层支持，且覆盖四种访问模式。

## 全局数据

- 根作用域：可读写、**不可 move**、必须声明访问模式。
- "统一结构"落地：程序提供全部实现框架——共享内存（模式化共享数据）+ 消息传递（`Channel<T>`），由使用方选择。

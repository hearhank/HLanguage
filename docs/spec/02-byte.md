# 02 · 字节化

一切数据（包括函数）都能转换为字节数组——这是"一切都是数据"的可操作定义，也是"传输/存储"的免费能力。

## 转换规则

- **块**：字节化 = 平凡 memcpy（内存布局即字节）。
- **树**：字节化 = 序列化压平（遍历引用图，递归展开为连续字节）。
- **函数**：字节 = 代码引用（模块 + 函数 ID）+ 捕获环境（若有）。反序列化后仍可调用，要求对应代码已加载到当前进程。
- **捕获规则**（配合生命周期）：三类捕获——值捕获（块/动态块，复制进环境）、move 捕获（树，所有权进环境）、ref 捕获（树引用，环境含双向引用指针）。**值/move 捕获的函数可字节化**；**ref 捕获的函数不可字节化**（活引用无法序列化，编译期检查）。

## 格式

- **可逆**：块可反序列化回树，引用关系恢复。树 ⇄ 块 双向。
- **自描述**：递归嵌套 + 类型标签。结构信息编码在格式中，跨语言、跨版本可解释。
- **引用无环约束（已决策）**：序列化引用的可达图必须是严格树——循环引用、自引用（含递归实例环）一律检测报错，序列化中止。类型级递归（链表、树等递归类型）允许，实例级成环禁止。先禁用，为将来图编码（ID 引用）留升级口。
- **共享引用（已决策：接受复制语义）**：被多处引用的节点序列化时复制两份，反序列化后为独立副本、共享关系丢失。接受此语义——"树是值"的哲学下共享本就罕见；需要共享的图结构将来随图编码一并解决。
- 代价：比偏移式（FlatBuffers）大、重建慢；字节方法层可提供压缩/索引优化通道。

## 字节方法

- 自动附加到**所有类型**的通用通道：序列化、反序列化、比较、散列、复制、传输、存储。
- 任何 `T` 自动获得 `to_bytes` / `from_bytes` 及派生操作——类型无需为此写任何代码。
- **只读 + 重建**：字节操作产出新字节/新值，不原地修改；显式写回才改变原数据（与"默认不可变"一致）。
- 类型层操作（`a.b = x`）与字节层操作并存：类型层负责日常结构化读写（编译器生成高效代码），字节层是通用旁路。

## 与生命周期/并发的衔接

- 传输/存储 = 字节化复制（数据本体留在作用域内，随作用域销毁；跨作用域存活走 move）。
- FFI 边界（C ABI）以字节数组为协议：字节化与 C 结构内存布局天然衔接；双向引用只作用于语言内部，跨边界时降级为纯数据传递。

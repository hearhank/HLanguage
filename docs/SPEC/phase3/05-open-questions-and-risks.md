## #4 序列化 schema 演进——设计定案（2026-08-18，组 C E1.3）

**问题**：传输/保存的序列化数据在类型变更（字段增删/改名/改型）后的兼容策略。

### 分层（按既有内建，见 `examples/02-idioms/50-serialization.hc`）

| 层 | 格式 | 版本策略 |
|---|---|---|
| 内建连续类型 `to_bytes`（Q36） | 直映射内存视图 | **无版本字段**——schema = 类型定义本身；跨版本兼容由「版本化包装格式」负责（下层） |
| 内建 class `to_json`/`from_json`（Q37） | JSON 对象 | **宽松加载**——`from_json` 忽略未知键、缺省字段用类型默认值；保存总是当前字段集 |
| 脚本生成存储格式（Q38 定制通道） | 自定义二进制 | **版本字节 + 迁移钩子**（本设计主体） |

### 版本布局（脚本生成二进制格式）

`script` 块从 `types.fields` 生成 `to_bytes`/`from_bytes` 时，内嵌版本字段：

```
payload := [u8 版本][u64 LE 长度][字段序列...]     // Q38 长度前缀在外层（帧/能力标记）
字段序列 := 每字段：[u8 类型tag][u8 长度][utf8 内容] 或 定长标量直写
```

- 版本字节置于 payload 首字节；`0` 保留（空/未初始化），`1` 起为真实版本。
- 长度前缀（Q38 `[u64 LE]`）是**帧/能力标记**，不承担 schema 版本职责——两者正交。

### 迁移钩子

脚本生成的 `from_bytes` 对「版本 != 当前」的输入执行**迁移链**（旧→新逐级）：

```
from_bytes(b):
    v = b[0]
    if v == CURRENT: 直解
    else: b' = migrate_v{v}_to_v{v+1}(b) 递归 until v == CURRENT，再直解
    然后跑 user_validate（校验通道，C1 组）
```

- **schema 演进表**由用户声明（当前语言无该元数据载体，本轮定「演进表 = 脚本内 `var` 数组」，未来可纳入 `types` 元数据扩展）：
  ```
  // schema(User) = v1 [name: String, age: i32]
  //              → v2 [+email: ?String]
  ```
  脚本遍历演进表生成每级 `migrate_vN_to_vN+1`（新增字段填默认值、删除字段丢弃、改名/改型需手写映射）。
- **保存总是当前版本**；加载旧版本宽松（缺字段默认值、多余字段忽略），迁移后再校验。

### 通道落点

- 序列化/校验/存储样板生成 = `script` 块（Q37/Q38 定制通道，E1.3）——`types.fields` 类型驱动，随定义自动更新。
- 内建 `to_json`/`from_json` 保留零配置路径；脚本生成产物为**覆盖**（同名函数优先）。
- 原生运行时 String 方法（`.concat`/`.len`）与 `String.from` 属 Phase 7 缺口：样板示例在 interpret/IR 全绿，原生侧计入 compile mismatch（见 `tag1/README.md` 基线）。

## 开放问题裁决（2026-08-22，ADR-0016）

> C2（J1：E6.1）开放问题裁决，grill-with-docs 访谈 4 子项全推荐。完整决策与理由见 [ADR-0016](../adr/0016-open-questions-adjudication.md)。

### #1 Debug 悬垂标记切换粒度 → **编译单元级**

- 按**编译单元（文件）**切换；CLI `hc run`/`hc test`/`hc build` 增 `--dangle=on|off|auto`（`auto` = Debug 开 / Release 关，默认）——第三阶段实施项
- tag1 既有 `debug_dangling` 开关对齐为此；函数/引用点级留 1.x 性能优化场景

### #3 无 GC 长运行脚本 Arena 惯例 → **机制就绪 + 惯例文档化 + `with_arena` 包装**

- 机制已就绪（`mem.Arena`），本项不新增机制；脚本惯例 = **每请求一个 arena**（服务/事件循环每轮新建、处理完整体回收）
- 标准库补 `mem.with_arena(fn)` 包装：进入建 Arena、退出统一回收（含 deinit），减少样板

### #5 注册中心治理 → **MVP 只做「唯一包名 + 指纹发布」，治理 1.0**

- 第三阶段 MVP：唯一包名（注册冲突拒绝）+ 发布带 build.zon 指纹签名；冲突仲裁/审计/取消失控等治理规则全部 1.0（B4 正式注册中心）
- B3 的 `hc pkg publish`/`fetch` + 指纹校验不阻塞；供应链校验随 B3 指纹落地

### #6 跨线程引用传递 Send/Sync 静态标记 → **语法先行、语义留 1.x**

- `Send`/`Sync` = 编译期接口（显式标注 + 可推导性验证）；协作式下仅编译期诊断，真并行检查 1.x 启用
- 不替代 Q18/Q19（协作式线程捕获安全由绑定/逃逸 + 冻结窗口保证）；详细编译期诊断语义归 C3（与惰性迭代、switch 守卫一并细化）

## 风险登记

| 风险 | 影响 | 对策 |
|---|---|---|
| **Debug 悬垂标记的簿记开销 vs Zig 零开销定位** | 目标销毁时标记指向它的指针（双向登记）有簿记 | Release 默认关闭（编译时选项）；性能敏感场景直接关闭；ADR-0003 记录该主动权衡；M4 用基准验证 |
| **LLVM 版本耦合**（Rust 绑定 churn） | 构建维护成本 | 锁定 LLVM 版本；后端抽象层隔离；长期学 Zig 增加自托管后端 |
| **VM 与 LLVM 后端语义漂移** | 双模式语义不一致（核心承诺被破坏） | 共享 IR 为唯一语义源；一致性测试套件为硬性 CI 门槛 |
| **自举失败风险**（重写编译器） | M9 延期 | 分阶段自举（工具链组件先行）；Rust 参考实现长期保留 |
| **长期单人项目倦怠/停滞** | 项目死亡 | 每阶段可演示成果；0.x 定期发布；社区策略（Q-A 定位欢迎社区） |
| **语法/语义扩散（scope creep）** | 语言冻结推迟 | 规范先行 + 一致性套件约束；未批准特性一律进开放问题清单 |
| **构建时脚本执行（供应链风险，评审 C3）** | 依赖包中的 `script` 块在构建时执行任意代码 | build.zon 指纹校验 + 依赖来源审计 + 文档警示；脚本 = H 核心子集（受限分配器/IO） |

## 系统编程缺口（内核编程场景，2026-08-14 评估登记）

以「完成操作系统内核编程」为验收场景的评估结论：**数据结构本体足够**（class/Continuous/packed/align/枚举/切片/指针自由/位运算/原子原语/显式分配器/error union）；**6 项底层机器能力缺失使 1.0 无法承担内核编程**（评估全文见 2026-08-14 会话记录）。**2026-08-18 组 H（ADR-0014）落地 4/6**：K1 无标签 union / K2 volatile / K4 整数↔指针 / K5 符号导出均已就绪；剩 K3 asm 与 K6 freestanding（1.x）。落点：本表 + `04-stdlib-scope.md` 系统编程扩展 + `02-milestones.md` 缺口小节。

|---|---|---|---|

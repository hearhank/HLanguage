# LSP工具实施计划

> 状态：设计完成，准备实施（2026-08-22）
> 
> 本文档记录H语言LSP（Language Server Protocol）工具的实施计划，包括设计决策、技术架构、任务拆分和验收标准。

## 一、设计决策汇总

经过grilling会话（2026-08-22），确定了以下核心决策：

### 1.1 功能范围

**标准集**：诊断 + 定义跳转 + 悬停提示 + 自动补全

- **诊断**：编译错误/警告，实时诊断当前文件，保存时诊断整个项目
- **定义跳转**：跳转到符号定义位置
- **悬停提示**：显示类型信息 + Markdown文档
- **自动补全**：关键字 + 标识符 + 字段/方法 + 导入建议

### 1.2 技术架构

**LSP库**：tower-lsp（基于tokio，异步支持）

**代码组织**：
- 独立二进制 `hc-lsp`（用于Zed扩展和其他编辑器）
- 子命令 `hc lsp`（用于测试和调试）
- 复用现有编译器前端（lexer/parser/semantic）

**异步模型**：async/await处理请求

**缓存策略**：文件级缓存（初期），文件变更时失效

### 1.3 Zed集成

**Zed扩展**：创建独立的Zed扩展，包含Tree-sitter语法和LSP配置

**Tree-sitter语法**：
- 从现有lexer/parser转换
- 逐步迁移：先核心语法，后完整语法
- 核心语法范围：表达式、函数、变量声明、基本类型、类、枚举、接口、命名空间、控制流

**扩展位置**：`extensions/zed/`

### 1.4 实现策略

**诊断触发**：混合模式
- 实时诊断当前文件（快速响应）
- 保存时诊断整个项目（确保正确性）

**项目感知**：识别build.zon，支持跨文件跳转和诊断

**文档注释**：`///` 格式（类似Rust），Markdown解析

**测试策略**：集成测试为主，使用LSP客户端库测试完整的LSP交互

### 1.5 开发计划

**阶段划分**：
- **阶段1**：诊断 + 定义跳转
- **阶段2**：悬停提示 + 自动补全

**任务拆分**：按阶段拆分，每阶段内拆分为≤1小时小任务

### 2.2 模块设计

#### 2.2.1 hc-lsp二进制

**职责**：
- 启动LSP服务器
- 处理LSP协议通信
- 管理文档状态和缓存

**关键组件**：
- `LspServer`：tower-lsp服务器
- `DocumentManager`：管理打开的文档
- `DiagnosticCache`：缓存诊断结果
- `ProjectContext`：项目上下文（build.zon解析）

#### 2.2.2 LSP核心处理器

**诊断处理器**：
- `textDocument/didOpen`：文档打开时触发诊断
- `textDocument/didChange`：文档变更时触发诊断（实时）
- `textDocument/didSave`：文档保存时触发诊断（全项目）
- `textDocument/publishDiagnostics`：发布诊断结果

**定义跳转处理器**：
- `textDocument/definition`：跳转到定义位置
- 需要维护符号表和位置映射

**悬停提示处理器**：
- `textDocument/hover`：显示类型信息和文档
- 需要类型推断和文档注释解析

**自动补全处理器**：
- `textDocument/completion`：提供补全建议
- 需要上下文分析和类型推断

#### 2.2.3 编译器前端复用

**复用模块**：
- `hc::lexer`：词法分析
- `hc::parser`：语法分析
- `hc::semantic`：语义检查
- `hc::errorcodes`：错误码表

**适配层**：
- `LspDiagnosticAdapter`：将编译器错误转换为LSP诊断
- `SymbolTableAdapter`：将符号表转换为LSP位置信息

### 2.3 Tree-sitter语法设计

#### 2.3.1 核心语法范围

**第一阶段（核心语法）**：
- 表达式：字面量、运算符、函数调用、闭包
- 声明：变量、常量、函数、类、枚举、接口、命名空间
- 控制流：if、while、for、switch、defer
- 基本类型：标量、数组、切片、元组、可选、错误联合

**第二阶段（扩展语法）**：
- 泛型和特性
- 错误处理细节
- 并发特性
- 元编程（script块）

#### 2.3.2 语法转换策略

**从现有parser转换**：
1. 提取语法定义（从parser.rs）
2. 转换为Tree-sitter grammar.js格式
3. 调整为CST（具体语法树）格式
4. 添加高亮、缩进、大纲等查询

## 五、风险与缓解

### 5.1 技术风险

**风险1**：Tree-sitter语法转换复杂度超预期
- **缓解**：逐步迁移，先核心语法，后完整语法
- **应急**：初期可仅依赖LSP，暂不提供语法高亮

**风险2**：诊断性能不满足要求
- **缓解**：实现文件级缓存，优化编译器前端
- **应急**：增加诊断防抖时间，降低实时性要求

**风险3**：跨文件依赖处理复杂
- **缓解**：复用现有build.zon解析逻辑
- **应急**：初期仅支持单文件诊断，跨文件诊断留待后续

### 5.2 资源风险

**风险4**：开发时间超预期
- **缓解**：按阶段拆分，每阶段独立可交付
- **应急**：优先实现诊断和定义跳转，悬停和补全留待后续

# H 语言规范：所有权与内存模型

> 对应实现模块：07 第一块语言系统 M2 语义 / M4 运行时。术语与情况全录以 `CONTEXT.md` §5 为准（2026-08-14 所有权情况全录）。
> **2026-08-29 修订（ADR-0030）**：所有权转移改为指针形态——参数 `owned *T`/`owned *mut T`，调用点 `move &t`/`move &mut t`（`move t` 为字面别名），move 后原变量冻结；值形态参数（`owned T`）不再用于转移。详见下文「转移（move, 2026-08-29）」。

## 核心模型

- **作用域** = 无名字的函数；函数 = 有名字的作用域；所有权注册在作用域上，退出自动销毁；**销毁顺序 = 声明逆序（LIFO）**（Q26 定案）
- **所有权 = 销毁责任的唯一归属（Q-S11 修订，Zig 式）**：同一时间只有一个对象（作用域或分配器）对「变量所在内存退出时销毁」负责——**不是访问权限控制**；非 Arena 分配器创建的复杂类型 → 销毁责任**默认注册当前作用域**（退出自动销毁；显式 `o` 冗余标注）；Arena 分配 → 由 Arena 统一负责销毁（归 Arena）
- 总原则（2026-08-14）：凡由分配器分配的对象都有所有权；global 与 Arena 分配的对象所有权归固定对象（根作用域/Arena），不可 move

## 所有权情况全录（2026-08-14）

- **A. 无所有权**：① 值类型（标量/连续类型）——栈内存随作用域退出天然回收；② 指针/切片自身——栈上地址值，销毁责任在指向的目标；③ Arena 分配的对象——归 Arena 统一回收
- **B. 有所有权（责任人）**：① 非 Arena 分配 → 当前作用域；② Arena → Arena；③ global → 根作用域（程序退出时销毁）；④ 复杂类型字段带 `o` → 父对象（赋值时 move 到父）；⑤ `copy()` 新对象 → 当前作用域
- **C. 转移（move, 2026-08-29 修订）**：① **指针形态**：参数 `owned *T`/`owned *mut T`，调用点 `move &t`/`move &mut t`；`move t` 为 `move &mut t` 字面别名（非 mut 变量报错）；② 字段带 `o` 赋值 → 父对象；③ 线程捕获（第三块 E2）；④ **禁止 move**：Arena 分配、global 变量（内存由 Arena/全局对象管理）、未标注 owned 的变量；⑤ **move 后原变量冻结**（后续使用编译错误，重新赋值复活）；⑥ 返回推断：`return` 堆分配构造或 `return &mut expr` → 签名 `T` 推断为 `owned *mut T`（裸值 return 不推断）
- **D. 销毁时机**：① 作用域退出递归销毁一切有所有权子对象；② 根作用域退出（程序结束）；③ Arena 统一回收；④ 显式销毁仅限资源（文件句柄等）→ `defer`

**属性无所有权标注（2026-08-14 Q3 定案）**：class 的属性（字段）无所有权标注——即使字段类型为  `owned T`（拥有），所有权由**类型实例**管理（随实例销毁），不属作用域；`pub mut A: owned T` 中 pub（可见性）/mut（可写）/ `owned T`（类型形态）分离。

## 引用与指针

- **指针自由（Q-S11 修订，Zig 式）**：变量可有多个读写指针（`*mut`）与多个只读指针（`*T`）；**指针问题（悬垂/别名）由用户负责**；唯一写者概念取消；`*mut` 可复制
- **引用类型赋值 = 编译错误（2026-08-14 修订，取代 Q3c 别名共享）**：`var s2 = s1;`（数组/集合/String 等引用类型）**不合法**——共享数据走显式指针 `var p = &s1;`（指针问题用户负责），复制走显式 `copy(&s1)`（新建内存、有所有权）；`copy` 默认深复制，浅复制需显式标注（如 `copy(&s1, .shallow)`），浅复制引入的内存问题由用户负责。标量/连续类型赋值即复制（值语义）
- **move（2026-08-29 修订，取代 2026-08-14 H2 重述）**：move 的语义 = **把有所有权的变量的「销毁的权力」以指针形态转移**——不复制数据、不移动内存。**合法形态**：`move &t` / `move &mut t`（调用点，取引用表达式前缀）；`move t` 是 `move &mut t` 的字面别名（非 mut 变量报错）。**move 后原变量冻结**（后续使用编译错误，重新赋值复活——旧「原绑定仍可访问」废止）。**返回推断**：签名 `T` + `return` 堆分配/`return &mut expr` → 自动推断 `owned *mut T`。仅对标注 `owned` 且分配来源为全局分配器的变量合法（Arena/global 禁止）
- **可移动性（2026-08-29 修订）**：三条件——① 变量标注 `owned`；② 分配来源 = 全局分配器（Arena/global 禁止）；③ 未移出过（affine）。指针别名自由（用户负责），不阻塞 move

## 指针细节

- `*T` 只读指针：**多个可同时存在**（Q-S11 修订）；指针问题用户负责；Debug 悬垂标记可选（编译时选项）
- `*mut T` 可写指针：**多个可同时存在（唯一写者概念取消）**；`*mut` **可复制**（「不可拷贝只能 move」取消）；指针问题用户负责；**Debug 悬垂标记**（目标销毁时标记指向它的指针，访问已标记指针 → 提示带位置）为可选诊断工具（编译时选项，非安全保证）
- **指针不可空**（Q16 定案）：`*T`/`*mut T` 永远指向有效对象或已被标记悬垂；空态用 `?*T`/`?*mut T`；无 NULL 字面量；悬垂 ≠ null
- **临时引用生命周期（Q25 定案）**：表达式产生的临时 `*T`/`*mut T` 存活到所在完整表达式/语句结束；绑定到变量的引用存活到作用域结束（原「唯一写者资格/链末注销/reborrow」语义随唯一写者取消而移除）
- **运行时错误（Q-S11 修订）**：**唯一写者冲突概念取消**（多读写指针合法）；Debug 悬垂标记开启时访问已标记的悬垂指针 → 诊断提示（工具性质，非安全保证）；悬垂属用户责任（Zig 式）；与 error union（可恢复）正交

## 内存机制

- **Allocator 方法集（C2 定案，2026-08-14）**：`alloc.alloc(n) &[u8]`（**字节分配**）/ `alloc.init(T)` 与 `alloc.init(T{字段 = 值, ...})`（**按类型创建实例**，两种形态见 06-03）/ `alloc.deinit()`（释放——Arena 统一回收场景）；旧 `arena.alloc(T{...})` 类型形态**废弃**；字节分配保留（`arena.alloc(256)` ✅）
- **Arena**：批量分配器——一次分配大量内存、统一回收（`Arena.init(alloc)` / `arena.alloc(n)`（字节）/ `arena.init(T)`（类型）/ 作用域退出自动统一回收或显式 `deinit`）；**Arena 分配的对象无所有权**（归 Arena，禁止 move——move 须对整个 Arena 进行）；适用请求级生命周期
- **o 默认规则**（Q16）：非 Arena 分配器创建的复杂类型默认由作用域负责销毁（退出自动销毁，无需显式 o/deinit）；Arena 例外（统一销毁）；`defer` 管非内存资源（文件等）
- **defer/errdefer**：资源清理（不用隐式析构）；多 defer 按 LIFO（Q21）
- **无 GC**：双模式同一套模型（Avoid: 引用计数）

## 已知限制（2026-08-25；2026-08-29 部分被 ADR-0030 取代）

以下为当前 `owned` 变量检查的已知限制，将在后续版本逐步解决：

1. **`alloc.init(T)` 无 `destroy` 方法**：`alloc.init(T)` 创建的值无法通过 `defer x.deinit()` 释放，因为分配器 API 尚无 `destroy` 方法。当前方案：移除 `alloc.init(T)` 变量上的 `owned` 标注，待分配器 API 添加 `destroy` 后恢复。

2. **`Thread::join()` / `detach()` 未触发 `move` 标记**：`var t: owned Thread<i32> = spawn(f, args); t.join();` 中的 `join()` 方法消耗了 `Thread` 的所有权，但当前检查器不识别方法调用为所有权转移，会报错。当前方案：相关 `Thread` 示例在 `examples/` 中且不在测试套件内，暂不触发。后续需为 `join()`/`detach()` 添加特殊处理。

3. ~~**函数参数和返回类型中的 `owned` 不被跟踪**~~：**2026-08-29 起被 ADR-0030 取代**——参数 `owned *T`/`owned *mut T` 与返回推断（`T` → `owned *mut T`）正是新模型的核心检查对象，Rust semantic 在 K6 前实现。

4. **赋值不触发 `move` 标记**：`doc.tag = tag;` 将 `tag` 的所有权转移给 `doc.tag`，但当前检查器不识别赋值操作为所有权转移。需显式 `move` 或 `defer`。新模型下字段转移建议 `doc.tag = move &tag;` 形态（待实现）。

5. **`NonArena` 来源自动跟踪已回退**：之前尝试自动跟踪所有 `NonArena` 来源的变量，但过于激进（包括了 `alloc.init(T)` 等无 `deinit` 方法的类型）。当前仅跟踪显式 `Type::Owned` 标注的变量。

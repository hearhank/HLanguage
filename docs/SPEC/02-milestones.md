## M0 项目奠基（1–2 月）

**目标**：建立仓库、工具链、文档体系与测试基建。

- [ ] 初始化 Git 仓库与 CI（lint + 测试 + 文档构建）
- [ ] Rust cargo 工作区骨架（编译器 crate + 运行时 crate + 工具链 crate）
- [ ] 测试基建：语法快照测试、语义测试、双模式一致性测试的框架
- [ ] 文档体系定稿：CONTEXT.md / SPEC / ADR / RESEARCH 归档
- [ ] 决策记录补全：0001–0004

**验收**：`hc --version` 可运行；CI 全绿；文档齐备可追溯。

**依赖**：无。

## M1 前端：lexer / parser / AST（3–6 月）

**目标**：完整解析 H 的核心语法（C 风格）。

- [ ] lexer：关键字、标识符、字面量、运算符、注释、`snake_case` 惯例
- [ ] parser：表达式优先级、语句、块作用域、函数（有名字的作用域）
- [ ] AST 表示与位置信息（行列/偏移，供全部诊断使用）
- [ ] 诊断基础设施：错误带精确位置；多错误收集
- [ ] 命名空间解析（namespace 块 + `using` 引入 + `pub` 包边界的语法层面，Q21 C# 式）

**验收**：核心语法 100% 可解析；错误报告带行列位置；语法快照测试覆盖基线建立。

**依赖**：M0。

## M2 类型系统（4–8 月）

**目标**：静态强类型 + 显式标注为主、局部推断为辅。

- [x] 名称解析与符号表
- [x] 类型检查：基本类型、结构体、数组、函数签名（2026-08-16：M2.2 完整——表达式级类型检查/期望类型传播/字段索引校验/存储形态验证/运算符接口族/泛型 where 约束调用点验证）
- [x] 局部类型推断（绑定处；函数签名显式）
- [x] error union 与显式错误集的分析（M2.6：成员检查 + anyerror 不约束 + **错误码表**——名↔码全局唯一、包 ID + 包内码编码、首次出现位置，2026-08-16）
- [ ] 结构化类型兼容（脚本模式可选特性）
- [x] 类型元数据：为「定义数据」支柱的序列化打基础（连续/堆上形态判定）

**验收**：类型错误可精确定位；error set 分析完整；类型测试套件通过。

**依赖**：M1。

## M3 脚本生成与 comptime（4–7 月）

**目标**：元编程双轨（2026-08-13 修正）——脚本生成（`script` 作用域）+ 语言内 comptime 式功能（泛型/类型级计算）。

**M3.0 前置子阶段（Q28 定案，2026-08-13：脚本 VM 子集边界）**：

- [ ] 单线程脚本解释器 = 词法/解析（M1 产出）+ 求值 + **作用域所有权 + defer + 错误处理 + 集合/String + `types` 元数据查询**（Q23）——脚本自身运行所需的最小 H 语义（B1「H 核心子集」）
- [ ] **延迟项（不进 M3.0）**：Debug 悬垂标记、多线程/async——脚本内引用不检测（脚本 = 编译期工具代码，生成代码的完整语义由编译后端保证）
- [ ] 脚本执行 = 编译期/编辑期工具路径，不受 M4 内存模型完整实现阻塞；M4 可与 M3 并行
- [ ] **降级闸门（Q-S10 定案）**：若 M5 后 VM/LLVM 一致性无法通过或脚本生成器成本超预期 → 1.0 降级为「脚本生成 = 编译期执行 H 子集函数（comptime 内联）」，`script{}` 语法保留、实现走编译期求值（B1 预案）

- [ ] `script` 作用域语法与解析
- [ ] 脚本解释器：编译前执行脚本并生成代码（M3.0 子集即可满足；生成脚本需要的语言能力：IO/集合/错误处理——IO/集合为脚本受限环境）
- [ ] comptime 式编译期求值（编译期函数、类型即值、`anytype`）——服务泛型
- [ ] 生成代码注入机制（脚本块生成 H 声明/函数/类型）
- [ ] 实时预览与校验通道（脚本解释器的编辑器集成，衔接 M8 LSP）

**验收**：脚本生成与 comptime 测试套件通过；可用泛型（comptime 式）与数据定义样板（脚本生成）；编辑器内实时预览可用。

**依赖**：M2；脚本执行依赖 **M3.0 脚本 VM 子集**（Q28 定案：单线程、无引用登记、无多线程）。

## M4 内存模型（5–9 月）

**目标**：实现 Allocator + 作用域所有权 + 双向引用跟踪 + 悬垂检测。

- [x] 所有权/作用域分析：有/无所有权判定、作用域销毁代码生成（tag1：运行时来源判定 + LIFO 销毁 + 编译时分配来源跟踪，2026-08-16）
- [x] `move` 语义：所有权转移分析（tag1：编译时合法性检查——Arena/global/值类型禁止，2026-08-16）
- [x] 数据栈对象判定：自包含连续内存类型的编译器判定（S2 规则）（tag1：[continuous] 字段值类型验证，M2.2）
- [x] 引用检查：只读/读写区分（**指针自由**：多 `*mut`/`*T` 合法，无唯一写者约束——Q-S11）（tag1：多指针合法 + 引用赋值禁止 + 引用逃逸 Q18，2026-08-16）
- [x] Debug 悬垂标记（编译时选项，可选诊断）：目标销毁时标记指向它的指针，访问已标记指针 → 提示带位置（非安全保证）（tag1：cell 内容标记方案，2026-08-16）
- [x] 悬垂检测：Debug 标记 + 访问抛错（带位置）；Release 裸读路径（tag1：`debug_dangling` 开关，2026-08-16）
- [x] Allocator 传递（显式参数 + 全局回退）（tag1：alloc/arena 内建注入）

**验收**：内存测试套件（含悬垂场景）通过；Debug 泄漏检测生效；Release 路径零簿记开销（基准验证）。

**依赖**：M1、M2（引用检查需要类型信息）。

## M5 双后端（6–10 月）

**目标**：共享 IR + 字节码 VM + LLVM 原生后端，双模式语义一致。

> 注：字节码 VM 核心已按评审 C2 提前至 M3（脚本生成依赖）；M5 聚焦 LLVM 原生后端与双模式一致性。

- [x] 共享 IR 定义（唯一语义源；禁止两后端各自语义）（tag1：`hc/src/ir.rs` 线性指令 + 参考解释器 `lower`/`run_ir`，标量/控制流/错误值通道/限定名调用，2026-08-16）
- [ ] 字节码 VM + 运行时（脚本模式，启动快）
- [ ] LLVM 后端（Rust inkwell/llvm-sys 绑定，锁定版本）
- [ ] 双模式一致性测试套件：同一程序两种模式跑出相同结果（含 test 块，Q-T5：`hc test --mode=compile` 交叉验证）
- [ ] 脚本启动时间指标（TS 式低摩擦目标）

**验收**：同一程序双模式结果一致（一致性套件通过）；编译产物独立运行；脚本启动时间达标。

**依赖**：M4（内存模型决定运行时形态）、M2。

## M6 错误与运行时报告（3–5 月）

**目标**：错误 union 运行时、`try` 传播、悬垂错误报告。

- [x] error union 运行时表示与 `try` 传播（tag1：`Value::Err { name, code }` 码运行时表示 + 值通道传播 + catch 全链拦截，2026-08-16）
- [x] 悬垂访问错误的触发与报告（带出错位置）（tag1：`DanglingPointer` 带位置，M2.5）
- [x] 不可恢复错误策略（panic 式，可配置中止/回卷）（tag1：`@panic` abort + 根作用域 panic 式中止，无 unwind/recover）

**验收**：错误测试套件通过；悬垂错误报告含触发位置。

**依赖**：M5 后端基础（可与 M5 并行）。

## M7 标准库四大支柱（9–15 月）

**目标**：四大数据操作的标准库模块稳定可用（范围见 `04-stdlib-scope.md`）。

- [ ] 定义数据：comptime 驱动序列化/反序列化
- [ ] 修改数据：集合/容器/变换
- [ ] 传输数据：网络、IPC、FFI/C 互操作
- [ ] 保存数据：文件、存储、数据库接口
- [ ] 端到端示例程序（同时用到四大支柱）作为验收基准

**验收**：每支柱 API 稳定 + 测试覆盖；端到端示例可双模式运行。

**依赖**：M5、M6。

- [ ] `hc build`（一键构建）
- [ ] `hc test`（测试块收集 + 断言 API + 输出统计，Q8/Q-T1/Q-T2）
- [ ] `hc cc`（C 互操作编译）
- [ ] 包管理器（内置编译器）+ 官方注册中心（自托管 MVP）
- [ ] LSP、格式化、lint

**验收**：`hc build` 一键构建示例项目；`hc test` 输出 PASS/FAIL/SKIP 与汇总统计、失败非零退出码；`hc pkg add` 可用；LSP 提供诊断。

**依赖**：M5（编译能力）、M7 部分。

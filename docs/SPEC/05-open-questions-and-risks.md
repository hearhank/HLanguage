# 开放问题与风险登记

## 开放问题（待后续细化）

按项目所有者要求「存在问题先标注，后期讨论更详细的计划」。

| # | 问题 | 背景 | 建议方向 |
|---|---|---|---|
| 1 | **只读引用 Debug/Release 切换粒度** | S1 定案「Debug 默认注册、Release 默认裸读」，但切换粒度未定：编译单元级、函数级还是引用创建点级？ | 倾向编译单元级（简单可预测）；函数级留给性能优化场景 |
| 2 | **`*mut` 指针的传参 reborrow 语义**（2026-08-13 标注） | `*mut` 不可拷贝（评审 A5）但函数借用参数（`fn f(v: *mut T)` 非 move）需要传递指针——传参是「重新借用（reborrow）」还是不允许？与唯一写者登记的交互（调用期间写者资格如何过渡） | Rust 式自动 reborrow：调用期间暂时转移写者资格，返回后恢复；需运行时登记支持 |
| 2 | **无 GC 下的长运行脚本** | 脚本模式无 GC，依赖作用域回收；长运行脚本（服务、事件循环）的内存增长模式需 Arena/批处理约定 | 标准库提供作用域 Arena（`mem.Arena`）并推广为脚本惯例 |
| 3 | **序列化与 schema 演进** | 传输/保存的序列化数据在类型变更后的兼容策略（版本字段？迁移？） | 二进制格式设计时内置版本与迁移钩子 |
| 4 | **官方注册中心的治理** | 包名冲突、安全审计、取消失控 | 起步用自托管 MVP，治理规则 1.0 后再完善 |
| 5 | **跨线程引用传递** | 双向注册的运行时簿记与线程边界的关系（Send/Sync 式静态标记如何与运行时簿记配合） | 静态标记先行（M2 类型层），运行时簿记不做跨线程 |

> ✅ **已关闭（2026-08-13）**：~~唯一写者的强制机制~~ —— 定案为**运行时登记**（双向引用注册冲突即抛错），见 ADR-0003/0005。

## 风险登记

| 风险 | 影响 | 对策 |
|---|---|---|
| **双向引用簿记开销 vs Zig 零开销定位** | 性能敏感场景不达标 | Release 裸读路径已兜底；ADR-0003 记录该主动权衡；M4 用基准验证 |
| **运行时唯一写者登记的额外开销** | 每个 `wr` 引用创建/销毁有登记簿记 | 登记簿记与双向引用簿记复用同一机制；Release 下评估可关闭项（待基准） |
| **LLVM 版本耦合**（Rust 绑定 churn） | 构建维护成本 | 锁定 LLVM 版本；后端抽象层隔离；长期学 Zig 增加自托管后端 |
| **VM 与 LLVM 后端语义漂移** | 双模式语义不一致（核心承诺被破坏） | 共享 IR 为唯一语义源；一致性测试套件为硬性 CI 门槛 |
| **自举失败风险**（重写编译器） | M9 延期 | 分阶段自举（工具链组件先行）；Rust 参考实现长期保留 |
| **长期单人项目倦怠/停滞** | 项目死亡 | 每阶段可演示成果；0.x 定期发布；社区策略（Q-A 定位欢迎社区） |
| **语法/语义扩散（scope creep）** | 语言冻结推迟 | 规范先行 + 一致性套件约束；未批准特性一律进开放问题清单 |
| **构建时脚本执行（供应链风险，评审 C3）** | 依赖包中的 `script` 块在构建时执行任意代码 | build.zon 指纹校验 + 依赖来源审计 + 文档警示；脚本 = H 核心子集（受限分配器/IO） |

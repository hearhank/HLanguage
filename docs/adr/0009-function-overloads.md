# 函数体系：重载 / 可选参数 / 泛型约束验证

2026-08-14 项目所有者定案（推翻此前「函数名唯一」隐含假设）：

- **允许重载**：函数签名 = **函数名 + 参数类型列表 + 返回类型**（共同决定）——`fn describe<i32>`、`fn describe(&[u8])`、`fn describe(f64)` 可共存；返回类型参与签名但仅在**目标类型已知时**参与调用点选择（`var x: f64 = get();` 选返回 f64 的重载）
- **调用点解析**：按参数精确匹配；字面量（惰性宽度）匹配多个重载或上下文歧义 → **编译错误，要求显式标注**（与「推断优先、显式兜底」Q-S9 同哲学）
- **可选参数**：`fn f(a: i32, b: i32 = 0)`——默认值须**编译期常量**；只能出现在参数列表**尾部**；解析优先精确参数数量匹配
- **泛型重载**：泛型函数（where 约束）在调用点**编译时验证**约束——验证通过即可调用；**接口限制运行时拆除**（单态化静态分发、无虚表、无运行时检查——零开销）；泛型与具体重载并存时统一参与解析（无「具体优先」特殊规则，按 Q1a 歧义规则）
- **边界**：接口方法（如 INumber 的 `add`）为**成员契约**，不参与全局重载解析；`new` 样板由脚本生成（参数按字段）；`box`/`copy` 为编译器内建不可重载；**运算符重载仍禁止**（运算符只绑定内建接口族）

选择理由：重载提升 API 表达力（同语义不同型）；返回类型参与签名配合推断优先（TS 式上下文定型）；泛型编译时验证 + 运行时拆除 = 静态分发零开销（与「性能为先」一致）；可选参数减少样板（替代部分重载需求）。

代价：重载解析复杂度（歧义诊断需清晰）；返回类型参与签名在调用点无目标类型时会歧义报错（需显式标注，样板增加）；泛型与具体重载并存时解析顺序需在 M2 实现细化。

落点：01 §12.5（重载与可选参数）、§12.16（泛型约束验证）、06 §5、CONTEXT §3 唯一处理逻辑、示例 87-overloads.hc。

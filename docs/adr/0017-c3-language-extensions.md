# C3 语言扩展定案：惰性迭代契约 / switch 守卫 / Send·Sync 编译期诊断

> 2026-08-22 定案（C3 = J2 三项，grill-with-docs 访谈，3 子项全推荐；惰性迭代按选项 C「只补迭代契约」）。关联：SPEC [06-01-syntax.md](../SPEC/06-01-syntax.md)（§4 switch 守卫）、[06-05-interfaces.md](../SPEC/06-05-interfaces.md)（Send/Sync 标记接口）、[06-10-concurrency.md](../SPEC/06-10-concurrency.md)（Send/Sync 诊断）、[01-unimplemented-features.md](../phase3/01-unimplemented-features.md)（C3 / A7 条目）、[02-syntax-rules.md](../phase3/02-syntax-rules.md)（§5 语句规则 / §7 类型规则）、查询手册 [H Language.md](../H%20Language.md) §7 / §4、ADR-0016（#6 Send/Sync 语法定案）。

## 背景

- C3（J2：E6.1）三项：惰性迭代、switch 守卫、Send/Sync 静态标记（编译期诊断）——落点 `semantic.rs` + 迭代契约
- **惰性迭代与 A7（1.x 惰性/组合子迭代器）冲突**：A7 与迭代契约已登记 1.x；C3 列第三阶段项——需澄清「设计」vs「实现」边界
- Send/Sync 语法形态已由 ADR-0016 #6 定案（编译期接口：显式标注 + 可推导性验证），详细编译期诊断语义归本 ADR

## 决策

### C3-1 惰性迭代 → **只补迭代契约（选项 C），真惰性求值留 1.x（A7 不动）**

1. C3 的「惰性迭代」= **迭代器对象 API 与迭代契约补定**（设计文档先行），不涉及惰性求值运行时改造
2. 迭代器对象形态：`arr.iter()` 为**显式数据对象**（可传递/组合）——补定 `iter()` 返回的迭代器方法签名：`next(self: *mut Self) ?T`（按对应访问形态）+ `filter(fn)` / `map(fn)` 组合子**签名与语义定案**（返回新的显式迭代器对象，链式可组合）
3. **惰性求值（`next()` 按需求值、链式延迟计算）真实现仍留 1.x**——A7 状态不变（1.x 延迟），不推翻既有判定
4. 与「无隐藏控制」原则对齐：迭代器对象/组合子为**显式数据对象**，非隐式求值机制；迭代进程可见可控（一次性迭代器 1.0 已满足）

### C3-2 switch 守卫 → **Rust 式 `模式 if 守卫 => 表达式`**

1. 语法：**`switch (v) { 模式 if 守卫 => 表达式 }`**——守卫在模式后、`=>` 前；守卫可为任意布尔表达式，可引用负载捕获变量（`int => |i| i if i > 0 => ...`）
2. **守卫失败 → 继续尝试下一个分支**（不报错、不落入该分支）
3. **穷举性**：有守卫的分支仍算覆盖该值形态，但守卫可能失败 → 需存在无守卫分支或 `else` 兜底保证穷举（否则编译错误）
4. 仍是表达式（每个分支产出值；守卫失败走后续分支求值）；与既有 `else` 兜底（Q31）正交叠加

### C3-3 Send/Sync 编译期诊断 → **内建标记接口 + 可推导性验证 + spawn/await 边界诊断**

1. **形态**：`Send` / `Sync` = **内建标记接口**（同 ICompare/INumber 族风格，编译器内建实现，不可用户自定义/重载）；用户类型 `class Foo: Send` 显式标注（implements 冒号后缀，与既有接口一致）
2. **可推导性（组合性验证）**：
   - 标量/值类型（Continuous/元组/枚举）自动 `Send`+`Sync`
   - 指针/切片看指向类型；`Vec`/`Map`/`Table`/`String` 等内建容器看元素/负载类型
   - 用户标注 `class Foo: Send` / `: Sync` 由编译器验证字段全满足才合法（含 `*mut` 或可变共享 → 非 `Sync`）；验证失败编译错误
3. **诊断模式（协作式，编译期）**：`spawn`/`await` 边界捕获跨线程引用，若目标类型非 `Send` → **编译错误带位置**（`captured value of type X is not Send at spawn boundary`）；非 `Send` 值不可跨线程捕获
4. 与 Q19 关系：Q19 冻结窗口管**借用期**（主线程不可写），Send/Sync 管**类型层契约**（跨线程可传递性）——两者正交叠加，不替代 Q18/Q19
5. **真并行检查（运行时）1.x 启用**——协作式下仅编译期诊断，零运行时开销，不破坏确定性承诺

## 理由

- C3-1 选项 C：不推翻 A7 的 1.x 判定；迭代器对象 API 定案即可推进「设计完整」，「无隐藏控制」张力不动（真惰性求值需运行时改造，价值不抵确定性承诺破坏）
- C3-2 Rust 式守卫：模式后守卫贴近 Rust/Zig 惯例、可引用负载捕获、守卫失败继续下分支语义可预测；穷举性规则与既有 else 兜底正交，实现最简
- C3-3 内建标记接口：与标量接口族风格一致（编译器内建实现，无虚表、零开销）；组合性验证复用既有接口标注通道；协作式下诊断只增强不破坏——为 1.x 真并行铺类型层地基

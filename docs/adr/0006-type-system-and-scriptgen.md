# 类型系统与元编程：struct / 复杂类型 / 接口 / 脚本生成

2026-08-13 项目所有者重构类型系统与元编程机制（三参考语言均无此组合，为 H 自主设计）：

- **struct**：值类型，底层连续内存（字节数组）；字段只含标量、struct、定长数组、切片；**不含复杂类型字段**（堆数据一律进复杂类型）
- **复杂类型**：堆上类型，用关键字声明（1.0 最小集 `class`、`tree`，家族可扩展）；连续或不连续内存；**组合形式**，字段可含标量、struct、其它复杂类型，字段可带 `o`
- **接口**：方法契约集合，**显式声明实现**（Rust 式）；可描述复杂类型、标量、内建类型、用户 struct；不提供运算符重载
- **脚本生成替代 comptime**：`script` 作用域标注脚本代码，编译前由脚本解释器执行并生成代码（对应 Zig 的编译时生成，用脚本表达）；脚本用 H 编写，解释器支持实时预览与校验

选择理由：脚本生成与双模式执行同源（H 的脚本模式即生成器运行时）；「以数据为中心」= 数据定义驱动四大支柱样板生成；接口显式实现符合「没有隐藏控制」。

代价：失去 Zig 式编译期求值的紧耦合（comptime_int 等退化为纯类型规则）；脚本运行器需在编译前可用（M3 依赖脚本模式 VM 的先行子集，里程碑排期调整）。

**2026-08-13 修正**：语言内**保留 Zig 式 comptime 功能**（泛型等类型级计算：编译期函数、类型即值）；脚本生成负责样板与数据定义驱动的代码生成。分工已确认（X1）：comptime 管类型级计算（泛型、类型即值、惰性实例化、comptime_int）；脚本生成管样板与数据定义驱动代码生成。

**2026-08-13 评审补充（A4/B1/D1）**：① 脚本生成**必须实现**（核心特性），但「数据定义 → 样板」场景下脚本功能**可选**（comptime 承担生成）。② 脚本语言 = **H 核心子集**（在特定分配器、特定 IO 下运行，尽可能与 H 核心一致）——若摩擦过大，后续可定义受限子集。③ 表述统一：「脚本生成与 comptime 双轨」。

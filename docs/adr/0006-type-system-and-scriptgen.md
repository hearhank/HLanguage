# 类型系统与元编程：struct / 复杂类型 / 接口 / 脚本生成

2026-08-13 项目所有者重构类型系统与元编程机制（三参考语言均无此组合，为 H 自主设计）：

- **struct**：值类型，底层连续内存（字节数组）；字段只含标量、struct、定长数组、切片；**不含复杂类型字段**（堆数据一律进复杂类型）
- **复杂类型**：堆上类型，用关键字声明（1.0 最小集 `class`、`tree`，家族可扩展）；连续或不连续内存；**组合形式**，字段可含标量、struct、其它复杂类型，字段可带 `o`
- **接口**：方法契约集合，**显式声明实现**（Rust 式）；可描述复杂类型、标量、内建类型、用户 struct；不提供运算符重载
- **脚本生成替代 comptime**：`script` 作用域标注脚本代码，编译前由脚本解释器执行并生成代码（对应 Zig 的编译时生成，用脚本表达）；脚本用 H 编写，解释器支持实时预览与校验

选择理由：脚本生成与双模式执行同源（H 的脚本模式即生成器运行时）；「以数据为中心」= 数据定义驱动四大支柱样板生成；接口显式实现符合「没有隐藏控制」。

代价：失去 Zig 式编译期求值的紧耦合（comptime_int 等退化为纯类型规则）；脚本运行器需在编译前可用（M3 依赖脚本模式 VM 的先行子集，里程碑排期调整）。

**2026-08-13 修正**：语言内**保留 Zig 式 comptime 功能**（泛型等类型级计算：编译期函数、类型即值）；脚本生成负责样板与数据定义驱动的代码生成。分工已确认（X1）：comptime 管类型级计算（泛型、类型即值、惰性实例化、comptime_int）；脚本生成管样板与数据定义驱动代码生成。

**2026-08-13 评审补充（A4/B1/D1）**：① 脚本生成**必须实现**（核心特性），但「数据定义 → 样板」场景下脚本功能**可选**（comptime 承担生成）。② 脚本语言 = **H 核心子集**（在特定分配器、特定 IO 下运行，尽可能与 H 核心一致）——若摩擦过大，后续可定义受限子集。③ 表述统一：「脚本生成与 comptime 双轨」。

**2026-08-13 Q2 裁定（struct 字段集放宽）**：struct 字段可含复杂类型（String/集合/class），与 class 成员集一致（Q22）。纯 POD struct（字段全为标量/纯值 struct）为连续字节、可 `to_bytes` 直映射；含堆字段的 struct 本体仍内嵌字段值（指针+长度），序列化走递归（非 POD）。struct 与 class 差异收敛为：值语义（可内嵌、无分配器）vs 堆上引用类型（需分配器）。此前「struct 不含复杂类型字段」表述由本裁定取代。

**2026-08-13 Q17 定案（接口指针表示）**：`*Shape` 接口指针 = 胖指针（data 指针 + 虚表指针，两字宽）；`box` 装箱产生，具体指针 → 接口指针**编译期自动收窄**（接口实现检查）；胖指针 data 部分参与双向引用登记（悬垂检测/唯一写者与普通指针一致），虚表不参与（编译期静态）。接口引用无运行时安全例外——与内存模型单一路径。

**2026-08-13 Q22/Q22b/Q22c 定案（接口参数 = 虚拟类型 + where 约束）**：接口类型传参用**带约束的虚拟类型**，约束放签名末尾 where 子句：`fn add(a: *T) void where T: INumber`。形态映射 `&T`→`*T`（只读）/ `&mut T`→`*mut T`（可写）/ `move T`→`o T`（拥有）；调用点 `add(&a)` / `add(&mut a)` / `add(move a)`。静态分发（单态化无虚表）为主路径；动态分发（`*Shape` 胖指针装箱）保留给异构集合。io 参数：库函数统一 `io: *T where T: Io`；入口 `fn main(io: Io)` 为编译器注入特例。

2026-08-13 Q23 定案（脚本输入机制）：script 块 = 编译前执行的 H 表达式块（H 核心子集），产物 = 生成代码字符串，就地替换本块；输入 = 上下文隐式 `types` 元数据对象（`types.fields("Person")` / `types.type("Person")` / `types.all()`），由编译器从类型系统生成注入；脚本用 H 字符串操作遍历类型定义拼接生成代码，无第二语言。

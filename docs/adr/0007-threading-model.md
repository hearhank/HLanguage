# 多线程模型：四模式类型 / 线程所有权 / 捕获规则

2026-08-13 项目所有者定义多线程模型（三参考语言均无此组合，H 自主设计）：

- **四模式共享类型**：单读单写/单读多写/多读单写/多读多写 = 内建泛型**共享内存容器** `Pipe<T>`/`Tee<T>`/`Funnel<T>`/`Hub<T>`；写者数量由类型名保证（单写者无锁路径、多写者互斥）；脚本生成实例化
- **线程所有权**：spawn 归当前作用域；作用域退出：已完成→销毁、运行中→所有权移交根作用域（**无隐式阻塞**）；显式 `join() !T` 消耗所有权，错误以 error union 跨线程传播
- **捕获规则**：值类型复制值；引用类型必须 move 所有权或为 global（**无只读引用捕获**——线程可能比作用域长寿，防悬垂）；线程捕获 ≠ 闭包捕获（12.9）

选择理由：「以数据为中心」——共享状态是「数据 + 访问控制」的容器，而非散落的锁原语；线程所有权与捕获规则从根上杜绝悬垂（无隐式阻塞符合「没有隐藏控制」）；错误处理跨线程一致（error union）。

代价：四模式类型需精心实现同步原语（单写者无锁、多写者互斥）；线程移交根作用域后的回收需运行时支持；Send/Sync 式静态标记需与运行时簿记配合（SPEC 开放问题 #5）。

2026-08-13 Q19 定案（线程捕获静态检查）：① **绑定/逃逸判定**（数据流）——句柄（Thread/Future）在声明作用域内被 join/await = 绑定（可捕获引用）；被 detach 或退出未 join = 逃逸（引用捕获编译错误）。② **冻结窗口**——绑定场景下，被捕获引用目标在 spawn 到 await/join 之间主线程不可写（`var mut` 写入/`&mut` 借用均编译期禁止），await/join 后恢复；并发写共享数据显式走四模式类型。两检查均为编译期，与运行时唯一写者登记正交。

2026-08-13 Q-S11 条注：上段「与运行时唯一写者登记正交」中的**唯一写者登记已随 Q-S11 取消**（指针自由，多 `*mut`/`*T` 合法）——冻结窗口为**线程安全约束**（防数据竞争），与指针自由无冲突：指针自由管访问资格（指针问题用户负责），冻结窗口管跨线程写入时序（编译期强制），两者正交性不变。

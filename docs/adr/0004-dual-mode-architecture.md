# 双模式执行架构：共享前端 → 共享 IR → 双后端

H 承诺「同一份源码既可编译为原生二进制，也可作为脚本执行，语义一致」（双模式执行）。架构为**单一前端与单一 IR，两个后端**：字节码 VM（脚本模式，启动快）+ LLVM 原生代码生成（编译模式，性能高）。

选择该架构而非「两套独立实现」或「单一 JIT VM」：共享前端与 IR 是「双模式语义一致」这一核心承诺的唯一可靠保证（两套实现必然语义漂移）；字节码 VM 满足脚本「秒启」需求（TS 式低摩擦）；LLVM 满足原生交付需求（Zig/Rust 式）。单一 JIT VM 的预热与交付形态不满足「编译成可交付二进制」的目标。

原生后端初始用 LLVM（Rust 生态成熟）；长期可学 Zig 增加自托管后端，将 LLVM 降为可选进程级依赖。

2026-08-13 Q-T5 定案（双模式测试）：`hc test` 默认脚本模式（VM，启动快）；`hc test --mode=compile` 在编译模式（LLVM 原生）跑同一套测试——双模式语义一致承诺延伸到测试；M5 一致性测试套件用编译模式交叉验证（同一 test 块两模式结果一致）。

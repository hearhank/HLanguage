# 语法功能说明为唯一规范依据

现有语法描述散落在 `docs/SPEC/phase1/06-*` 系列、`docs/H Language.md`、`docs/native-types.md` 等处，四类来源（ADR 定案、规范描述、实现快照、功能清单）互相矛盾且与 tag1 实现不同步（2026-08-30 盘点发现 14 处矛盾，含程序入口 4 个版本并存、并发模型两套口径、move 语义未同步 ADR-0030）。决定：新建 `docs/SPEC/syntax/`（一模块一文件），以「目标语义 + 实现状态标记（✅/⚠️/⏳/❌）+ 证据路径」的形式，作为一切功能实现与语法检查的唯一依据。

裁决次序：有 ADR 定案的以 ADR 为准（代码滞后记入实现待对齐清单）；无 ADR 的描述与代码矛盾逐条交项目所有者裁决；描述了但无实现无 ADR 的保留为规范目标并标 ⏳。旧 06-\* 系列加废弃横幅；`H Language.md` 降级为历史资料；`native-types.md` 降级为实现快照，均不再作为规范维护。stage1/stage2（自举链路）不在本规范覆盖范围，其所需语法以本规范描述的 tag1 行为为准。

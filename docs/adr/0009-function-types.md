# 0009 · 函数类型体系：`func<返回, 参数...>` + 参数权限四类标注

## 决策

函数类型名统一为 `func<返回, 参数...>`（替换早期拼写 `fun(...) -> R`）。第一个槽位是返回类型，后续按序是参数类型；每个槽位都带权限标注：

| 标注 | 语义 | 对应旧拼写 |
|---|---|---|
| `T` | 值复制（**仅块**；树参数用 `T` → R5 报错，消灭"树默认只读指针"的隐式规则） | `x: T`（块） |
| `*T` | 只读引用 | 树默认参数 |
| `*mut T` | 可写引用 | `ref T` |
| `move T` | 所有权转移 | `move T` |

返回类型统一同一套标注：`func<*mut Str, u64>` = 入参 u64、返回可写引用 Str；`func<move Acc>` = 返回所有权。`active<参数...>` = `func<void, 参数...>` 的别名（无输出函数，纯语法糖，不引入"副作用/纯函数"类型区分）。

`fun` 关键字保留：函数定义 `fun name(params) -> R { }`、闭包字面量 `fun(x: T) [caps] -> R { }` 不变；只有**类型位置**用 `func<...>`（变量/参数/返回类型标注）。

## 理由

- **签名自描述**：`func<u64, *mut Str>` 一眼看清返回/参数/权限，无映射层；定义与类型同拼写（`fun f(p: *mut Str) -> u64` ↔ `func<u64, *mut Str>`）。
- **显式哲学**（Zig 血统）：消灭"树参数默认只读指针"的隐式规则，所有权限显式标注。
- **与闭包机制衔接**：闭包/函数引用共用同一类型，`fun` 字面量 + `func` 类型名职责分离。

## 拒绝的选项

- 参数保持 `ref`/裸 `T`、`*T`/`*mut T` 只在类型签名用——两套拼写并存，需映射规则（签名与定义不一致）。
- `active` 作为独立语义类型（副作用 vs 纯函数）——副作用是运行时行为，不进类型系统。
- 保留 `fun(...) -> R` 为唯一拼写——与参数权限四类标注无法自然融合（`*mut T` 在箭头式签名里无位置）。

## 影响

- 已实现机制（`fun(u64) -> u64` 闭包/函数引用，`closure.hc`/`optional_fun.hc`）需迁移类型名拼写；参数标注换新（`ref` 退守变量指针声明与 ref 字段）。
- 变量/指针拼写不变：`mut` 可变声明（无 `let`）、`ref view = acc` 变量级可写指针。

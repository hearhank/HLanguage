# 系统编程范围定案：K1–K5 纳入；K6 freestanding 延迟至 1.x

> 2026-08-18 定案（第三块前置裁决 A4）。关联：[05-open-questions-and-risks.md](../SPEC/05-open-questions-and-risks.md)（系统编程缺口表）、[04-stdlib-scope.md](../SPEC/04-stdlib-scope.md)（系统编程扩展）、[02-milestones.md](../SPEC/02-milestones.md)、执行细表 [10-part3-execution.md](../SPEC/10-part3-execution.md)。

## 背景

- **05 系统编程缺口表（2026-08-14 评估）**：以「完成操作系统内核编程」为验收场景，判定数据结构本体足够，**6 项底层机器能力缺失**（K1–K6）使 1.0 无法承担内核编程
- **分级**：K1–K6 = 阻断性缺口（内核无法开工）；K7–K11 = 重要缺失（可绕行，1.x 候选）
- **状态建议**：K1 无标签 union「需设计决策，建议 1.0 纳入（M2 类型系统）」；K2 volatile / K4 指针转换「机制级，建议 1.0 纳入」；K5 符号导出「机制级，建议 1.0 纳入（M8）」；K3 内联汇编「已标注 1.x」；K6 freestanding「需设计决策：无 std 目标（LLVM 后端专用）；1.0 范围裁决」
- **本块目标**（07 §五）：扩展功能 + **自举**；系统编程非自举前提

## 决策

1. **K1–K5 本块内纳入**（除 K3）：均为**机制级**能力，量级小（各 1–2h）、语言语义独立、不依赖自举，按 05 建议实施：
   - **K1 无标签 union**（组 H1）：`union { a: i32, b: f32 }`——字段**内存重叠**、无判别标签、大小 = 最大字段（对齐 = 最大对齐）；构造/字段访问经 `@ptrCast`/union 字面量；与 enum 区分（enum 带标签，union 纯内存双关）。语义对齐 C 风格 union（`@cImport` 映射前提）
   - **K2 volatile**（组 H2）：`@volatileLoad/Store` 机制级内建——LLVM volatile 语义（防优化掉副作用，MMIO 场景）
   - **K4 `@ptrFromInt`/`@intFromPtr`**（组 H3）：整数 ↔ 指针转换（物理地址 → 虚拟指针）
   - **K5 `export fn`**（组 H4）：符号导出 + 链接脚本钩子（段布局/对齐；`_start` 入口导出）
   - **K3 内联汇编明确 1.x**（不阻塞，05 已标注）：特权指令非本块范围
2. **K6 freestanding 延迟至 1.x（自举后）**：
   - 理由：① K6 = 无 OS/无 libc/无默认分配器的**独立目标**（LLVM 后端专用）+ 从 std 抽取 H core（无 OS 依赖核心）——大工程，非「机制级」；② 不服务本块目标（扩展功能 + 自举前奏）；③ 04 已标「1.x 候选，不阻塞 1.0 用户态系统编程」；④ 与「H 编译 H 前」范围边界一致
   - 组 H5（K6）移出本块；`04-stdlib-scope.md` 系统编程扩展标注「1.x（K6）」
3. **K7–K11 维持 1.x 候选**（05 表状态不变）：裸函数指针/位域/指针算术/端序原语/原子变量类型——可绕行，不阻塞

## 影响

- **执行细表**：组 H 按 K1/K2/K4/K5 实施（H1–H4）；**H5（K6）移出**；H6 文档同步勾选 05 状态
- **语义层**：`union` 类型（M2 类型系统扩展）、`export` 标注、`@volatileLoad/Store`/`@ptrFromInt`/`@intFromPtr` 内建
- **后端**：LLVM 发射支持 union 布局、volatile 语义、export 符号、链接脚本参数
- **文档**：06-02-types（union）、06-04-functions（export/@ 内建）、05 状态表、02 里程碑、04 系统编程扩展标注
- **未变**：K7–K11 状态；04「1.x 候选」结论；系统编程缺口评估（05）整体有效性

## 取舍

- 选择「K1–K5 纳入、K6 延迟」而非「全纳入或全延迟」：K1–K5 是量小、语言语义独立的机制级能力，立即价值高（FFI/内核准备）；K6 是量大的独立目标工程，放到自举后的 1.x 更有收益（届时 H 语言/工具链成熟，H core 抽取更顺）；代价是「本块即可写内核」不可达（05 已明示 1.0 不阻塞用户态系统编程，内核编程本非本块验收）
- 选择「K1 union 语义对齐 C」而非「自定义安全 union」：`@cImport` 映射前提（E3.5 FFI 需要 C union 直映）；H 的安全由**显式错误集/类型检查**在 union 之外提供，union 本身是裸内存工具，与指针自由（Q-S11）一致——低级能力用户负责，不做隐藏防护

# TypeScript 实现事实清单（截至 2026）

> 为 H 语言设计调研而整理。TS 的事实高度稳定，本文件基于公开官方信息整理；如需精确引用，以 https://www.typescriptlang.org 与 https://github.com/microsoft/TypeScript 为准。

## 1. 时间线与 1.0

- 2012-10 由微软发布（0.8 预览版）；**1.0 于 2014-04 发布**（约 2 年，快速冻结路线）。
- 现状：5.x 为当前稳定系列（2025 年微软宣布正在开发原生编译器，代号 TypeScript 7，Go 移植版——本文件以当前稳定 5.x 为准）。

## 2. 编译器架构与自举

- **自举**：tsc 用 TypeScript 自身编写，运行在 JavaScript 引擎上。
- 职责：类型检查 + **转译（transpile）到 JavaScript**（类型擦除，无类型信息残留），不是字节码 VM，也不是原生编译。
- 无独立运行时——运行在宿主 JS 引擎（V8/JSC/SpiderMonkey）上。

## 3. 类型系统

- **渐进式/可选类型**（gradual typing）：JS 是动态语言，TS 在其上叠加可选的静态类型标注。
- **结构化类型**（structural typing）：类型兼容性按形状（结构）判断，而非名义类型（nominal）。
- **类型推断**：标注可选，推断为默认；`any`/`unknown` 逃生舱。
- 类型系统是 TS 的核心价值，但运行时类型会被擦除（无运行时类型信息）。

## 4. 内存管理

- 无自己的内存管理，继承宿主 JS 引擎的 **GC**（分代追踪式）。
- 对开发者完全透明。

## 5. 错误处理

- 异常机制：`throw` / `try` / `catch` / `finally`（继承 JS）。

## 6. 并发

- 单线程事件循环 + 异步 I/O：Promise / async-await；Web Worker 提供并行。

## 7. 工具链

- npm 生态（包管理）、tsconfig（项目配置）、tsc 单文件编译器。
- 构建是「转译」而非「编译+链接」，天然适配脚本工作流。

## 8. 与 H 设计的相关性要点

- 「脚本模式」的参照：低摩擦（无需显式构建步骤即可运行）、即时反馈。
- 渐进式类型对 H 的启示：如果脚本模式需要更高摩擦容忍度，可选标注 + 推断是 TS 的答案。
- TS 的转译路径依赖「宿主语言」（JS）——H 没有宿主语言，脚本模式必须自建解释器/VM，不能照搬转译模式。
- TS 2 年到 1.0 的快速冻结路线，是 H 设定 1.0 节奏时可参照的务实选项。
